OpenWrt 安装 AdGuardHome

约 3319 字大约 11 分钟

2025-09-17

通过在OpenWrt上安装AdGuardHome，可以实现广告过滤和DNS过滤功能，提高网络访问速度和安全性。

  • OpenWrt环境
  • AdGuardHome核心安装及设置
  • luci-app-adguardhome可视化界面
  • AdGuardHome配置
  • AdGuardHome和OpenClash配合使用

AdGuardHome核心安装及设置

AdGuardHome核心是AdGuardHome的核心程序，用于处理DNS请求和广告过滤。

可以在AdGuardHome核心中下载最新的版本。

我这里直接在OpenWrt中的软件包搜索adguardhome，然后安装的。

安装完成之后访问http://<OpenWrt IP地址>:3000，即可看到AdGuardHome的Web界面。第一次会重定向到http://<OpenWrt IP地址>:3000/install.html，需要设置管理员密码。然后进行配置。

然后可以进行配置，我这里由于80端口被占用，选择的81端口。默认的53端口已经被Dnsmasq占用了，所以我们将AdguardHome的端口使用54。

配置完成后，我们通过http://<OpenWrt IP地址>:81访问AdGuardHome的Web界面。

luci-app-adguardhome可视化界面

luci-app-adguardhome是一个OpenWrt的可视化界面，用于配置AdGuardHome，安装之后可以在OpenWrt的Web界面中直接配置AdGuardHome。

可以在luci-app-adguardhome中下载最新的版本安装。

这个链接地址已经很久没有更新过了，有点儿老了。于是我又找到个近期还在更新的地址stevenjoezhang/luci-app-adguardhome

下载最新的安装包，然后上传到OpenWrt中安装。完成之后刷新页面，就能看到AdGuardHome的配置界面了。

这里我遇到个问题，核心服务的执行文件路径和配置文件路径和默认的不一致，导致无法启动。需要更新为真实的AdGuardHome的路径。

进入OpenWrt的命令行，运行下面命令查看AdGuardHome的信息

root@OpenWrt:~# ps | grep AdGuardHome
 4747 root     1235m S    /usr/bin/AdGuardHome -c /etc/adguardhome.yaml -w /var/lib/adguardhome --pidfile /run/adguardhome.pid --no-check-update
11275 root      1180 S    grep AdGuardHome

这里我们可以看出：

  • AdGuardHome 执行文件路径为：/usr/bin/AdGuardHome
  • 配置文件路径为：/etc/adguardhome.yaml
  • 工作目录为：/var/lib/adguardhome

我们进入OpenWrt->服务->AdGuardHome->核心设置。可以确认默认的几个信息和上面的是否一致，如果不一致需要修改为一致。

我这儿默认的配置如下：

  • AdGuardHome 执行文件路径为：/usr/bin/AdGuardHome/AdGuardHome
  • 配置文件路径为：/etc/AdGuardHome.yaml
  • 工作目录为：/var/lib/AdGuardHome

可以看出这里主要有两个地方不一致，这应该是我通过软件包安装，导致路径不一致。我们更新为一致即可。这时就能在AdGuardHome的管理页面看到正确的状态了。

AdGuardHome配置

安装AdGuardHome核心和luci-app-adguardhome后，可以通过OpenWrt的Web界面进行配置。

在OpenWrt的Web界面中，找到AdGuardHome的选项，点击进入AdGuardHome的配置。

有几种方式在OpenWrt中接入AdGuardHome：

  • 作为dnsmasq的上游服务器
  • 作为OpenClash的DNS服务器

作为dnsmasq的上游服务器

将AdGuardHome作为dnsmasq的上游服务器，可以dnsmasq收到dns请求后会转给AdGuardHome处理

只需要手动配置dnsmasq转发到AdGuardHome的54端口就可以了，我这里默认将dnsmasq的DNS转发给了127.0.0.1#7874，即转给了OpenClash的DNS服务。

查看7874端口是否在监听：

root@OpenWrt:~# netstat -tulnp | grep :7874
tcp        0      0 :::7874                 :::*                    LISTEN      4420/clash
udp        0      0 :::7874                 :::*                                4420/clash

可以看到OpenClash在监听。

现在手动更新为AdGuardHome的DNS服务地址，即127.0.0.1#54。这时候访问网页，DNS就会到AdGuardHome处理了。

但这种方式存在一个问题，客户端这里所有的请求都显示为127.0.0.1，因为AdGuardHome收到的DNS请求都是dnsmasq转发过来的，不利于区分设备。

这里还有一个问题，由于在OpenClash中设置了本地DNS劫持，所以手动设置dnsmasq将DNS转发到AdGuardHome的54端口后。刷新页面，又被修改为127.0.0.1#7874了。

OpenClash中设置了本地DNS劫持会自动修改 dnsmasq 的 server 配置项，强制指向它自己的监听端口（如: 7874 ），以确保所有 DNS 流量经过加密代理。

设置AdGuardHome的DNS服务端口为53

主要原则是将dnsmasqde的DNS服务端口由53（入站NDNS查询的侦听端口）设置为54，然后将AdGuardHome的DNS服务端口设置为53（入站NDNS查询的侦听端口）。这样就让所有DNS查询都到AdGuardHome去了。

确认了AdGuardHome和dnsmasq的DNS服务端口后，接下来需要将dnsmasq的DNS服务端口由53改为54，并将AdGuardHome的DNS服务端口改为53。

可以通过图形界面或手动设置实现端口交换，将AdGuardHome的DNS重定向模式设置为使用53端口替换dnsmasq。

可以在界面中或者命令行中查看，dnsmasq的DNS端口变为了54了。但是AdGuardHome的DNS端口设置的是53（通过/etc/adguardhome.yaml配置文件查看的）但是没有生效。试了几次都是不行，于是重启了AdGuardHome服务，发现AdGuardHome的DNS端口变为了53，dnsmasq的DNS端口变为了54。

重启之后，AdGuardHome的DNS端口变为了53，dnsmasq的DNS端口变为了54。交换了端口，现在所以的DNS请求都由AdGuardHome处理了。

现在由AdGuardHome处理DNS请求，也能通过IP区分设备了。但是我们之前配置的OpenClash就失效了，因为DNS现在不走dnsmasq了，dnsmasq的DNS转发到OpenClash的7874端口也就没有什么作用了。

AdGuardHome+OpenClash

有两种方式实现AdGuardHome+OpenClash：

  • 使用OpenClash内置的DNS服务，将AdGuard Home作为OpenClash的下游服务使用。
  • 用AdGuard Home替换Dnsmasq的53端口，AdGuard Home将DNS解释转发到OpenClash进行解释。

我们选择将AdGuardHome的上游DNS服务设置为OpenClash的DNS

  1. AdGuard Home重定向模式选择“使用53端口替换dnsmasq”，这一步我们前面已经做了。
  2. 将AdGuard Home的上游DNS设置成OpenClash的DNS监听端口127.0.0.1:7874，AdGuardHome->设置->DNS设置->上游服务器设置为127.0.0.1：7874。这里需要主要，测试上有服务器是失败的，我们直接点击应用就行了。
  3. 关闭OpenClash的本地DNS劫持。OpenClash->插件设置->DNS设置->本地DNS劫持。
  4. OpenClash的DNS设置里启用 自定义上游DNS服务器，自定义上游DNS服务器选择国内和google的DNS地址。OpenClash->复写设置->自定义上有DNS服务器

这样就完成了：DNS请求先由AdGuardHome处理，然后由OpenClash处理。

ikuai中设置首选DNS为部署了AdGuardHome的OpenWrt的IP地址。

问题

AdGuardHome 作为 DNS 入口（推荐）

这种方案下，所有DNS请求先经过AdGuardHome进行过滤，再转发给OpenClash做最终解析。这是目前更主流、也更清晰的配置。

DNS 查询路径：设备 → AdGuardHome (53端口) → OpenClash (7874端口) → 公共DNS

关键配置：

AdGuardHome：在“DNS设置”中，将“上游 DNS 服务器”设置为 OpenClash 的监听地址 127.0.0.1:7874。 OpenClash： 本地DNS劫持：关闭。 自定义上游DNS服务器：关闭。 监听端口：确保 AdGuardHome 监听 53 端口，OpenClash 监听 7874 端口。 如果你按照此方案配置，请务必关闭“自定义上游DNS服务器”开关。

通过 AdGuardHome Web 界面重新生成配置

先手动启动 AdGuardHome（不带配置文件），它会自动进入初始化向导模式：

/usr/bin/AdGuardHome -s run

注意：这个命令会在前台运行，你会看到日志输出。

root@OpenWrt:~# /usr/bin/AdGuardHome -s run
2026/08/31 15:18:52 [info] AdGuard Home, version 0.107.57
2026/08/31 15:18:52 [info] service: control action: run
2026/08/31 15:18:52.162907 [info] AdGuard Home, version 0.107.57
2026/08/31 15:18:52.162921 [info] AdGuard Home is running as a service
2026/08/31 15:18:52.163076 [info] This is the first time AdGuard Home is launched
2026/08/31 15:18:52.163084 [info] Checking if AdGuard Home has necessary permissions
2026/08/31 15:18:52.163221 [info] AdGuard failed to bind to port 53: listen tcp 127.0.0.1:53: bind: address already in use

打开浏览器访问 http://10.0.0.3:3000，你应该会看到 AdGuardHome 的初始化向导页面。

按照向导进行配置：

监听端口：Web 管理界面保持 3000 不变。

DNS 服务器监听端口：设置为 53（这样 AdGuardHome 才能接管 DNS）。 我这里设置的是 54，后面再AdGuardHome的DNS 重定向模式中选择使用53端口替换dnsmasq，然后点击保存并应用就会自动更端口 工作目录备份路径/etc/AdGuardHome

上游 DNS 服务器：如果你配合 OpenClash 使用，填写 127.0.0.1:7874；如果暂时只想测试，可以填 223.5.5.5 或 114.114.114.114。

隐私保护：可以保持默认或关闭。

配置完成后，AdGuardHome 会自动生成 /etc/AdGuardHome/AdGuardHome.yaml 配置文件。此时按 Ctrl+C 停止前台进程。

现在用系统服务方式正常启动：

/etc/init.d/AdGuardHome enable
/etc/init.d/AdGuardHome start

再次检查端口占用：

netstat -tulpn | grep :53

这时你应该能看到 AdGuardHome 在监听 0.0.0.0:53 了。
